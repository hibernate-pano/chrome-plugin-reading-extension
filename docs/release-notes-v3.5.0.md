# Folio v3.5.0

发布日期：2026-09-29

这一版是修复月。除了一个新增功能外，大部分改动是修掉了几处**此前一直存在、但没人注意到**的缺陷——其中一处让所有代码块的语法高亮一直是坏的。

---

## 🕘 阅读历史面板

扩展一直在本地记录你读过的文章（最多 200 条），但此前**没有任何界面能看到它们，也无法删除**——这版补上了这个洞。

- 工具栏新增**时钟图标**，浮层列出最近读过的文章：标题、域名、相对时间（「刚刚」「3 天前」）、预计阅读时长
- 点标题在新标签页重新打开
- **每条可单独删除**；「清空全部」需二次确认
- 没有记录时显示明确的空状态
- 面板里直接写明：**阅读记录只保存在这台设备上，不会上传到任何服务器，可随时清空**
- 存储里的地址来自网页自身（`window.location.href`），属于外部可影响的数据，因此每条记录都会校验协议；非 http(s) 的地址降级为纯文本，**页面上不会出现可点击的危险链接**

设置面板同时新增「**恢复默认设置**」。

## 🐛 修掉的缺陷

### 代码高亮一直是坏的（影响最广）

阅读页和打印页的**每一个代码块**都受影响。之前的高亮器对同一段文本串行跑多轮正则替换，而前面几轮刚写回的 `<span class="token-comment">` 标签会被后面几轮**再高亮一遍**，产出 `<span <span class="token-keyword">class</span>=…>` 这种非法 HTML，浏览器解析后样式全面崩坏。

现在改为单遍扫描。顺带补上了 Python / YAML / Shell 等语言的 `#` 行注释，同时确保 CSS 的 `#header` 不会被误当成注释。

### 其他

| 现象                                             | 原因                                                                                                                   |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 打印时图片挂了，PDF 里是空框，**且没有任何提示** | 超时上限触发时仍在加载的图片既不计入成功也不计入失败，返回值与「这页没图片」完全一样，于是界面认为一切正常并撤掉了提示 |
| 「N 分钟阅读」严重偏小                           | 词数被重复除以 6，2000 词的文章显示成 2 分钟                                                                           |
| 点图标偶尔完全没反应，且没有任何提示             | 内容脚本若初始化失败就不再接收任何消息，之后彻底失聪                                                                   |
| 设置面板打开 3 秒后，工具栏自己消失              | 工具栏的显示逻辑依赖设置面板状态，导致隐藏定时器被意外重新挂上                                                         |

| 某些设置下排版整体塌陷                           | 设置校验放过了 `NaN`，会渲染出 `font-size: NaNpx`                                                                      |
| 反复导出 PDF 后可能失败                          | 打印载荷在会话存储里只删不漏                                                                                           |
| 复制代码失败时页面里残留隐形文本框               | 复制回退路径缺少 `finally` 保护                                                                                        |

## 📐 排版规格

导出 PDF 固定为 **A4 纵向**，正文栏宽 **174mm**（210mm 减去左右各 18mm 边距），上下边距 20mm。页面内的连续预览与实际打印使用同一套 CSS，因此所见即所得。

**打印页可调项：**

- 纸张主题：浅色 / 护眼
- 字号：9 / 10.5 / 11 / 12 / 13 pt
- 图片尺寸：大 / 中 / 小

**阅读页可调项：**

- 主题：浅色 / 深色 / 护眼
- 字号 12–32px、行高 1.2–2.0、行宽 600–1200px

## ⚠️ 已知限制

以下几条**不是 bug**，但容易让人误判：

- **预览不提供分页预览**。浏览器没有任何 API 能查询分页会断在哪里——分页由排版引擎在行级别决定，JS 观测不到。任何「预览」都只能是估计，而且经常是错的，不如不给。Chrome 的打印对话框里看到的是真实效果。
- **打印对话框请保持 A4、默认边距、100% 缩放**。改成别的纸张或自定义页边距，页内测量的分页决策就不再成立。
- **图片处可能留白**。过高的图片被限制在 150mm 以内以免跨页被裁切，过高的代码块和表格允许跨页——这可能让上一页末尾留下空白，这是两害相权取其轻。
- **需要登录才能看到的图片会失败**。扩展无法携带你的 Cookie，打印页会明确告诉你「N 张未能加载」，但图片位置会是空的。
- **生产版本不输出任何控制台日志**（含 `console.error`）。这是刻意的体积优化，代价是用户报障时控制台是空的。开发时请用 `pnpm run build:debug`。

## ⚠️ 破坏性变更

- **最低 Chrome 版本提升到 102**。PDF 导出依赖 `chrome.storage.session`（Chrome 102 起提供）。Chrome 88–101 的用户将无法安装本版本；即使装上，导出功能也会直接失败。
- 依赖从 43 个精简到 27 个，**运行时依赖只剩 3 个**（`@mozilla/readability`、`react`、`react-dom`）。其中 9 个 Radix UI 包、`zustand`、`turndown`、`lucide-react` 等从未被实际引用。**如果你 fork 了这个项目并依赖过那些包，需要自行处理。**
- `web_accessible_resources` 已移除。原先它把 `print.html` 对所有网站开放，等于任何网页都能内嵌本扩展的打印页；实测该声明从不需要（打印页由扩展自己打开），且其中引用的 `content.css` 根本不存在于构建产物中。
- 扩展页面的 CSP 收紧为 `script-src 'self'; object-src 'self'; worker-src 'self'`。

## 📦 安装

1. 下载 `folio-reader-v3.5.0.zip`
2. **先解压**（Chrome 不支持直接加载压缩包）
3. 打开 `chrome://extensions/`
4. 右上角开启「开发者模式」
5. 点击「加载已解压的扩展程序」，选择解压后的 **`dist` 文件夹**（不是 zip，也不是文件夹里面的子目录）

## 🖥️ 浏览器要求

- **Chrome 102 或更高版本**（Manifest V3 + `chrome.storage.session`）
- 本版本在 Chrome for Testing 上完成端到端验证：阅读模式、代码高亮、历史面板、PDF 导出全流程 31 项运行时检查全部通过
