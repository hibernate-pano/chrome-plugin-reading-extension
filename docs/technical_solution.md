# 1. 概述
本技术方案文档旨在详细描述 Chrome 阅读增强插件的技术选型、架构设计、开发流程和部署方案。该插件旨在为用户提供更舒适、高效、智能的网页阅读体验。

# 2. 技术选型
## 2.1 前端
+ 框架: React - 成熟稳定，拥有庞大的社区和丰富的生态，组件化思想有利于构建复杂、可维护的 UI 界面。
+ UI 库/样式: Tailwind CSS - 原子化 CSS 框架，可以快速构建样式，保持一致性，并方便自定义主题以贴合 Chrome 风格。基于其进行简单的UI组件封装，尽量减少对成熟UI库的依赖。
+ 状态管理: Zustand - 轻量级状态管理库，简单易用，性能出色，适合中小型项目。
+ 构建工具: Webpack 或 Vite  - 建议使用 Vite, 更快地进行模块打包和项目构建。
+ 语言: TypeScript - 静态类型检查，提高代码质量和可维护性。

## 2.2 AI 集成
+ 分段和重新排版:
    - 首选: OpenAI API (GPT 系列) - 强大的文本理解和生成能力，能够根据上下文进行智能分段和排版。
    - 备选:  Google Cloud Natural Language API - 提供文本分析功能，可以作为备选方案。
+ 翻译:
    - 首选: Google Translate API 或 DeepL API - 提供高质量的翻译服务，支持多语言互译。支持用户选择偏好的翻译引擎。
    - 备选:  Microsoft Translator API - 可作为备选翻译引擎。
+ 上下文释义:
    - 初期:  集成词典 API (例如 Merriam-Webster, Oxford Dictionary API)，提供基本的词汇释义。
    - 后续:  结合 OpenAI API (GPT 系列)，根据上下文生成更精准、更自然的解释，并提供例句。

## 2.3 数据存储
+ 用户偏好设置 (需同步): `chrome.storage.sync` - 存储需要在用户不同设备间同步的配置，例如主题、字体、行间距等。
+ 临时或设备特定设置: `chrome.storage.local` - 存储仅在当前设备使用的配置，例如最近阅读的页面、AI 模型选择等。

## 2.4 其他
+ 浏览器交互:  Chrome Extension API - 用于与浏览器进行交互，例如内容注入、事件监听、存储管理等。

# 3. 架构设计
## 3.1 模块划分
+ `content`:  负责与网页内容交互，提取正文，修改 DOM 结构，实现阅读模式。
+ `popup`:  插件的弹出窗口，用户交互的主要入口，用于设置选项、触发功能等。
+ `background`:  后台运行的脚本，用于处理一些后台任务，例如监听事件、管理状态等。也可以没有，完全依靠 `content` 实现主要功能。
+ `options`:  插件的选项页面，用于设置更详细的配置项。
+ `ai`:  封装 AI 相关的功能，包括与 AI API 的交互，处理 AI 返回的结果等。
+ `storage`:  封装数据存储相关的操作，提供统一的接口来访问 `chrome.storage.sync` 和 `chrome.storage.local`。
+ `ui`:  封装 UI 组件，提供一致的 UI 风格。
+ `utils`:  提供一些工具函数，例如字符串处理、DOM 操作等。

## 3.2 数据流
1. 用户在网页上触发插件功能 (例如点击图标、使用快捷键)。
2. `content` 脚本被注入到当前页面，提取网页正文内容。
3. 用户在 `popup` 或 `options` 中进行设置，设置信息通过 `storage` 模块存储到 `chrome.storage` 中。
4. `content` 脚本根据用户的设置，修改 DOM 结构，应用样式，实现阅读模式。
5. 如果用户使用 AI 功能 (例如分段、翻译、释义)，`content` 脚本会将文本内容发送到 `ai` 模块。
6. `ai` 模块调用相应的 AI API 进行处理，并将结果返回给 `content` 脚本。
7. `content` 脚本将 AI 处理后的结果渲染到页面上。

# 4. 关键技术实现
## 4.1 正文提取
+ 基于规则的方法:  根据 HTML 标签、class 属性、CSS 样式等规则来识别正文内容。可以使用一些成熟的库，例如 Readability.js。
+ 基于机器学习的方法 (未来):  可以使用机器学习模型来识别正文内容，提高准确率。

## 4.2 阅读模式
+ DOM 操作:  使用 JavaScript 操作 DOM，移除无关元素，调整样式，实现阅读模式。
+ 样式应用:  使用 Tailwind CSS 或自定义 CSS 来控制阅读模式的样式。

## 4.3 AI 分段
+ OpenAI API:  调用 OpenAI API 的文本生成接口，提供大段落文本和分段指令，获取分段后的文本。
+ 提示工程:  设计合适的 prompt，指导 AI 模型进行准确的分段。
+ 结果处理:  将 AI 返回的分段结果渲染到页面上，并允许用户进行手动调整。

## 4.4 翻译
+ Google Translate API / DeepL API:  调用翻译 API，将选中的文本或整个页面翻译成目标语言。
+ 多引擎支持:  提供选项让用户选择不同的翻译引擎。
+ 结果展示:  清晰地展示翻译结果，可以采用原文/译文对照的方式。

## 4.5 上下文释义
+ 词典 API:  调用词典 API，获取选中词汇的释义、音标、例句等信息。
+ OpenAI API:  结合上下文语境，生成更精准、更自然的解释，并提供例句。

# 5. 测试方案
+ 单元测试:  使用 Jest 对独立的函数或组件进行测试。
+ 集成测试:  测试不同模块之间的协作是否正常。
+ E2E 测试:  使用 Cypress 模拟用户操作流程进行端到端测试，确保插件在各种场景下都能正常工作。
+ UI 测试:  使用 Storybook 或类似工具进行 UI 组件的开发和测试。
+ 人工测试:  进行充分的人工测试，覆盖各种场景和边界条件。
+ 兼容性测试:  在不同版本的 Chrome 浏览器上进行测试。
+ 性能测试:  测试插件的性能，例如加载速度、内存占用等。

# 6. 部署方案
+ 打包:  使用 `vite build` 或 `webpack build` 打包插件代码。
+ Chrome Web Store:  注册开发者账号，按照 Chrome Web Store 的流程提交插件进行审核和发布。
+ 版本控制:  使用 Git 进行版本控制，建议采用 Git Flow 工作流。
