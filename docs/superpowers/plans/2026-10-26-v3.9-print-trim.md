# Folio v3.9 打印裁剪与排版密度 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让打印页能手动裁掉正文末尾的垃圾内容（段落级 + 页级快捷 + 撤销），并把行高与段距变成可调、可持久化的设置，顺带修掉几处让页数不可信的打印缺陷。

**Architecture:** 打印页是唯一的事实来源——`.p-doc` 在 174mm 列里被测量一次，切成真实的 A4 纸张，纸就是预览。v3.9 不新增第二套渲染：裁剪直接改动测量源里的 DOM（尾部节点被移除），然后走同一条 `clearBreakMarks → markOversizedBlocks → measureDocument → paginate → renderSheets` 重排路径。排版密度通过 CSS 变量（`--print-line-height` / `--print-para-gap`）作用于同一个测量面，所以预览和 PDF 不可能分叉。裁剪状态只存一个块 ID（`data-p-block`）和被摘下的节点引用，不存页码，改字号后截断点仍在同一段内容上。

**Tech Stack:** TypeScript 5 · Vite 5 · React 19（阅读器侧）· Vitest 4 + jsdom · Chrome MV3

**Spec:** `docs/superpowers/specs/2026-10-26-print-tail-trim-design.md`

## Review Focus

以下五类是规格暗示、但任何单个任务都不会自然覆盖、且最可能真的伤到用户的情况。每一类都在下面指定的任务里有对应测试。

1. **正好落在页首的块必须能被选中**：分页常常精确切在块边界上，此时 `docTop === pageStart`。用 `+0.5` 容差会漏掉本页第一个块，用户点了没反应。（Task 6 / Task 9）
2. **跨页续接的克隆永远不能当截断目标**：长段落、长代码块会横跨两页，下半截出现在下一页。点它会把上一页已经印出来的前半段一起删掉，用户看不到自己删了什么。（Task 6 / Task 8 / Task 9）
3. **裁剪必须扛得住改字号/行高/段距/图片大小**：重排之后截断点仍在同一段内容上，页数跟着更新，而且「撤销」入口必须始终可见——它是唯一的撤销入口，被藏起来就等于不可撤销。（Task 8）
4. **撤销时恢复的图片可能还没解码**：如果这次打印是从「无图」启动的，被恢复的图从未被等待过。必须先等图再分页，否则页数是错的。（Task 8）
5. **图片还在加载时不能打印**：否则纸上出现空白图框，而页数还是按旧布局算的。等待期间打印键与裁剪键都要禁用，且过期的等待结果不能把键重新打开。（Task 2）

### Task 1: 打印文档保留图注与段内文字

打印页现在会静默丢内容：`<figure><img><figcaption>图注</figcaption></figure>` 进了打印 DOM 之后 `figcaption` 数量为 0，因为 `processImage` 造了一个全新的 `<figure>`、替换掉父节点，然后只把 `<img>` 搬过去——图注留在被丢弃的旧节点里。裁剪之后用户会以预览为准，所以预览本身不能有洞。

- [ ] **Step 3: 实现等待闸门与 generation token**

`src/print/main.ts` 改动：

- 模块级新增：
  ```typescript
  let imageWaitGeneration = 0;
  let imageWaitPending = false;
  let bootReady = false;
  ```
- 新增 `updateControls()`：打印键的可用状态 = `bootReady && !imageWaitPending`。
- 新增 `waitForImagesFor(generation: number): Promise<ImageWaitResult | null>`：
  - 进入时 `imageWaitPending = true; updateControls();`
  - `await waitForImages(elements.sheet, 5000)`
  - 若 `generation !== imageWaitGeneration`（本次等待已被更新的操作取代）→ 直接返回 `null`，**不要**改 `imageWaitPending`、不要改状态条、不要触发重排。
  - 否则 `imageWaitPending = false; updateControls();` 并返回结果。
- `setImageSize` 开头 `const generation = ++imageWaitGeneration;`；目标尺寸是 `none` → `imageWaitPending = false; updateControls();`（取消在途等待）；否则走 `waitForImagesFor(generation)`，返回 `null`（过期）就直接 `return`，不再 `scheduleRemarking()`。
- `main()` 里的启动等待也走同一条路：`const generation = ++imageWaitGeneration;` 然后 `const result = await waitForImagesFor(generation); if (result === null) return;`。**并且**：等待语义从「只有离开无图才等」改成「目标尺寸不是 `none` 就等」——从「无图」启动的用户第一次切到大图时同样要等。
- `repaginate()` 末尾调用 `updateControls()`；`bootReady` 在**第一次** `repaginate()` 成功后置 `true`（放在 `repaginate` 内部，而不是 boot 末尾——这样"启动等待被用户操作顶掉"的路径也能完成启动）。
  - `repaginate()` 内部的顺序必须是：**先** `bootReady = true`，**再** `updateControls()`。反过来会让第一次分页结束时打印键仍然是禁用的。

- [ ] **Step 4: 实现 `src/print/trim.ts`**

要点：

- `assignBlockIds(content)`：遍历 `collectFlowBlocks(content)`，按顺序写 `block.dataset.pBlock = 'b' + (index + 1)`。**只分配一次**，重复调用会重新编号（调用方保证只调一次）。
- `cutTrailingFrom(root, target)`：
  1. `target` 不是 `root` 的后代（含 `target === root`）→ 返回 `[]`。
  2. 收集 `target` 到 `root`（不含 `root`）的祖先路径，自顶向下。
  3. 第 0 层：从 `target` 开始，删除它**和它之后的全部兄弟节点**。
  4. 第 k 层（k>0）：从该祖先的 `nextSibling` 开始删除其后所有兄弟节点，**保留祖先本身**（祖先里可能有目标之前的内容）。
  5. 每次删除记录 `{ parent, next, node }`，其中 `next` 是被删节点当时的 `nextSibling`。
- `restoreRemoved(removed)`：逆序遍历；`next` 还在 `parent` 里就 `parent.insertBefore(node, next)`，否则 `parent.appendChild(node)`。逆序是关键：同层被删的兄弟节点必须从右往左插回去，顺序才不会乱。
- `startsOnPage(block, pageStart)`：`Number(block.dataset.docTop)` 有限且 `>= pageStart - 0.5`。
  - 用 `-0.5` 而不是 `+0.5`：分页正好落在块边界时 `docTop === pageStart`，`+0.5` 会漏掉本页第一个块；跨页续接克隆的 `docTop` 严格小于 `pageStart`，`-0.5` 仍能排除它。

```typescript
import { decorateSheetForTrim } from '../../src/print/trim';

/**
 * A sheet built by hand, hung where the real ones are.
 *
 * jsdom has no layout engine, so `measureDocument` finds no blocks and the
 * rendered sheets come out empty. This mimics what `renderSheets` produces —
 * a `data-page-start` and one clone per block, carrying the source block's id
 * and the document offset it was measured at — and lets the real trim code
 * decorate it, so the buttons and the marks under test are the real ones.
 */
function fakeSheet(pageStart: number, clones: Array<{ id: string; top: number }>): HTMLElement {
  const el = document.createElement('div');
  el.className = 'p-sheet';
  el.dataset.pageStart = String(pageStart);
  const content = document.createElement('div');
  content.className = 'p-sheet__content';
  for (const clone of clones) {
    const node = document.createElement('p');
    node.dataset.pBlock = clone.id;
    node.dataset.docTop = String(clone.top);
    content.appendChild(node);
  }
  el.appendChild(content);
  (document.getElementById('pages') as HTMLElement).appendChild(el);
  decorateSheetForTrim(el);
  return el;
}
```
