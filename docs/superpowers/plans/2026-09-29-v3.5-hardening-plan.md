## 1. 已验证的缺陷（全部经代码走查 + 实测复现，非推测）

### P0-1 语法高亮产出的是损坏的 HTML —— 影响阅读页与打印页的每一个代码块

**位置**：`src/shared/codeHighlight.ts:118-134`

`highlightCode` 对同一字符串**串行执行 6 次 `String.replace`**，而前面几轮刚刚把 `<span class="token-comment">…</span>` 写回了字符串。于是后面几轮继续去"高亮"这些**自己生成的标签**。

实测输出（`highlightCode('// say "hi" now\nconst x = 1;', 'javascript')`）：

```
<span <span class="token-keyword">class</span>=<span class="token-keyword">class</span>="token-string">"token-comment"</span>>// say <span ...>"hi"</span> now</span>
```

`<span <span class=...>` 不是合法 HTML，浏览器解析后代码块样式全面崩坏。
`codeHighlight.ts:128` 的护栏 `if (match.includes('class="token-')) return match;` 恒不成立——单条正则只匹配注释/字符串/数字/关键字本身，不可能包含 `class="token-`；它是死代码。

**影响**：`CodeBlock.tsx:35`（阅读页）与 `buildDocument.ts:114`（打印页）共用此函数，两边同时坏。

### P0-2 阅读页缺少文章消毒，而打印页有 —— 两端不对称

**位置**：`src/content/extractor.ts`（无消毒）vs `src/print/buildDocument.ts:25-39`（有 `sanitize()`）

实测 Readability 对一篇含恶意标记的页面输出：

```html
<img src="http://…/x" onerror="window.__XSS__=true" alt="a">
```

`onerror` **存活**。该 HTML 随后由 `ReaderView.tsx:294/304/308` 经 `dangerouslySetInnerHTML` 注入 Shadow DOM。

诚实定级：注入内容来自用户当前所在页面，该页面本身就能执行脚本，因此**当前不构成权限提升**。但这仍是必须修的：两端行为不一致、依赖"来源页面本来就有权限"这一隐式前提、且一旦未来加入任何 main-world 桥接即立刻升级为高危。打印页已经做对了，正确做法是**提取共享消毒器，让两端走同一条路**。

### P0-3 `ReaderView` 元信息分隔符是恒真表达式

**位置**：`src/content/ReaderView.tsx:213`

```tsx
{content.siteName && (content.byline || true) && (
```

`(content.byline || true)` 恒为真。当前渲染结果碰巧正确，但这是把 bug 写进了条件里——任何后续改动都会踩。

### P0-4 `content/index.ts` 初始化失败会让内容脚本永久失聪

**位置**：`src/content/index.ts:36-43`

```ts
state.settings = await getSettings();      // 若抛错
chrome.runtime.onMessage.addListener(handleMessage);  // 永远不会执行
```

`getSettings` 内部已 catch，但 `initialize()` 整体仍在 try 内；一旦未来任一环节抛错，监听器不注册，此后点击图标、导出 PDF 全部无响应，且**没有任何用户可见提示**。

### P0-5 `enableReadingMode` 用旧设置写历史

**位置**：`src/content/index.ts:115-130`

`addToHistory(...)` 读 `state.settings`，而 `state.settings = await getSettings()` 的刷新发生在**它之后**。首次进入阅读模式时写入的是 `DEFAULT_SETTINGS`，不是用户真实设置。

### P0-6 阅读时长公式把词数又除了一次 6

**位置**：`src/shared/history.ts:95`

```ts
readingTime: calculateReadingTime((content.length || 0) / 6)
```

`content.length` 入参就是 `wordCount`（`types.ts:43` 注释明写 "Total word count"）。2000 词的文章算出 `ceil(2000/6/200) = 2` 分钟，正确值是 10 分钟。

### P0-7 会话存储里的打印载荷只删不漏

**位置**：`src/background/index.ts:158-172`

token 写进 `chrome.storage.session`，只有 `print/main.ts:223` 在**成功读到**时才删除。用户关掉标签页、中途报错、或刷新时机不对，key 就一直留到浏览器会话结束。文章 HTML 可能很大，累积占配额。

### P0-8 CI 不做类型检查，也不校验 manifest 与 package.json 版本一致

`.github/workflows/ci.yml` 跑 lint/test/build，无 `tsc`；manifest 校验只查 `manifest_version===3` 和文件是否存在。历史上 `package-lock.json` 就停在 `ai-reading-extension@2.9.0` 无人发现。
