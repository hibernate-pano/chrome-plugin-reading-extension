# Folio v3.7.0

纯阅读、零干扰——把任意网页变成干净的阅读视图，并导出为 A4 排版的 PDF。
无服务器、无统计、仅 3 个运行时依赖，所有数据只存在你自己的浏览器里。

本版本最大的变化：**打印预览现在按真实分页显示，你看到的就是打印出来的。**

---

## 📄 分页预览：所见即所得

点「打印 / 存为 PDF」后，文章会按 A4 真实分页，每一页独立成张，
右下角标注 **第 N / M 页**，工具栏实时显示总页数。改字号或图片大小时，
分页立即重新计算。

### 这推翻了此前的一个设计决定

从 v3.4.0 起，打印页一直带着一条明确的规则：**不提供分页预览**。当时的
理由写在代码注释里——

> 浏览器没有 API 可以查询断页会落在哪里。我们画出来的任何"预览"都只是一个
> 估算，看起来很权威，却经常是错的。

这个理由是对的，但有一个前提：**预览仅供参考**。也就是画一个猜测，再把同一份
文档交给 Chrome 重新分页一次——两边永远对不上，所以只能老实承认对不上。

现在换了个做法：**自己决定断页，然后直接打印这些纸。** 预览不再是输出的预测，
它就是输出本身。

具体怎么做到不失真：

- 文章只在真实的 174mm 行宽里**排版一次**，所有断页位置都从这次排版里量出来
- 每一页由落在该页区间内的内容块组成，块按量到的位置摆放，页面负责裁切
- 打印时每张纸正好是一个 A4 页面，浏览器没有剩余的分页决定权

### 断页规则

- **节标题不落页底**——不会出现一页最后一行是个孤零零的标题
- **段落两端各留至少两行**——不会在页首或页尾留下一行孤字
- **图片与表格不切**——宁可留白也不把图劈成两半
- **超过半页的代码块与长表格允许跨页**，避免整块被推到下一页留下大片空白
- **长列表在条目之间断开**，而不是从某个列表项中间切开

## ⚡ 性能

每页只复制属于这一页的内容块，而不是把整篇文章复制一份。
60 页的长文从 **58,000 个 DOM 节点降到约 1,000 个**。

## 📦 安装

1. 下载 `folio-reader-v3.7.0.zip` 并**解压**
2. 打开 `chrome://extensions/`
3. 右上角开启「开发者模式」
4. 点「加载已解压的扩展程序」，选择解压出来的 **`dist` 文件夹**

> Chrome 不支持直接加载压缩包，必须先解压再选 `dist` 目录。
>
> 浏览器要求：Chrome 102 或更高。

## 🖨 已知限制

这些**不是 bug**，但容易被误判为故障：

- **打印对话框请保持默认**：纸张 A4、边距「默认」、缩放 100%。分页由扩展
  决定，但打印机若换成 Letter（比 A4 矮 18mm），Chrome 仍会整体重排。
  **先看预览里的分页是否与打印对话框一致**，这是判断设置是否被改动的最快办法。
- **页面底部可能留白**：当页尾剩下的空间放不下下一张图或表格时，内容整体挪到
  下一页。这是刻意的——切开一张图比留白更糟。预览里能直接看到留白在哪。
- **需登录才能访问的图片会失败**：扩展不携带目标站点的 Cookie。
- **只提供 `srcset` 的图片会打印为空白**：`srcset` 在 HTML 消毒阶段就被整体
  剥离（页面可以用它决定加载哪些像素、花多少流量，这不是读者该替页面做的
  决定）。绝大多数站点同时给 `src`，那种情况不受影响。
- **跨标签页的阅读历史仍可能丢记录**：每个标签页是独立的模块副本，跨标签页
  并发无法用队列串行化。彻底修复需要改存储布局，属于后续版本规划。

## 🔒 权限说明

| 权限                 | 用途                             |
| -------------------- | -------------------------------- |
| `storage`            | 保存主题、字号、阅读历史         |
| `activeTab` / `tabs` | 在当前标签页启用阅读模式         |
| `scripting`          | 按需注入阅读脚本                 |
| `<all_urls>`         | 读取文章正文。经扩展商店审核需要 |

不收集任何数据，无网络请求，无遥测。
